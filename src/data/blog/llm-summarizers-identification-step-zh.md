原文标题：LLM Summarizers Skip the Identification Step<br>
原文链接：https://towardsdatascience.com/llm-summarizers-skip-the-identification-step/

![LLM Summarizers](https://towardsdatascience.com/wp-content/uploads/2026/05/tds_hero_redacted_document_1920x1080.png)

一个会议摘要器接收五分钟的对话，返回八个整洁的部分：决策、行动项、风险、待解问题——每个部分读起来就像是出自一个全程专注的人之手。

然而，阅读底层的会议记录，你会发现其中两个部分是从一个模糊的句子推断出来的，一个完全是凭空捏造的，三个则是从模型对"会议摘要应该包含什么"的先验知识中模式匹配得来的。措辞自信，格式规整，从结构上看与真实发生了这些内容的会议摘要完全无法区分。

这不是通常意义上的幻觉问题。模型并没有捏造关于世界的事实，而是在捏造关于这次会议的事实。而且这种失败模式在输出中并不可见——只是一堆读者难以与原始来源核实的自信文字。

这种失败模式在另一个领域有一个名字，而且比语言模型早得多。它就是在没有识别步骤的情况下进行估计时所发生的事情。

本文不是一个新的摘要基准测试，而是对一种设计模式的论证——我认为这种模式在 AI 工程文献中尚未被视为核心设计约束：将 LLM 生成的摘要视为对来源的结构化声明，要求每个声明声明其支持类别，并约束审查阶段只能弱化无支持的声明，而不是让输出听起来更流畅。我将逐步讲解在实践中这是什么样的，它产生什么结果，以及它在哪里会失效。

## 缺失的步骤

因果推断是将识别一个量与估计一个量之间的差异形式化的分析传统。[识别](https://towardsdatascience.com/identification-the-key-to-credible-causal-inference-c3023143349e/)是你拥有的数据能够支持你想要做出的声明的论证。估计是在识别确定后产生数字的程序。这个顺序不可商量。你不能估计一个你尚未论证可以从观测数据中识别的处理效应，因为所得到的数字是没有意义的——它看起来像是一种效应，但并不是。

在观测环境中工作的从业者会在识别上花费相当大比例的时间。他们绘制因果图，争论混淆因素，区分数据能够支持的内容和数据无法支持的内容。估计步骤最终到来时，往往是最容易的部分。

现在考虑一下 LLM 摘要器的做法。它接收一段会议记录，并生成关于该记录内容的结构化声明：做出的决策、接受的承诺、提出的风险、分配的下一步行动。每个声明从某种意义上说都是对一个潜在量的估计。决策是否做出了，承诺是否被接受了。摘要在断言每个量的值。

没有识别步骤。模型不会询问会议记录是否包含足够的证据来支持该声明，它产生声明是因为格式要求有一个声明。

*LLM 摘要的行为就像观测分析，但通常在没有任何类似识别步骤的情况下部署。*

AI 工程文献并非对潜在问题保持沉默。[幻觉检测](https://en.wikipedia.org/wiki/Hallucination_(artificial_intelligence))、校准不确定性、[选择性预测和弃权](https://arxiv.org/abs/1705.08500)、[RAG 接地](https://arxiv.org/abs/2005.11401)、引用验证、[事实一致性](https://arxiv.org/abs/1910.12840)和[声明核实](https://arxiv.org/abs/1803.05355)：每一项都是严肃的研究方向，每一项都解决了失败的一个真实层面。它们的共同之处在于，它们将捏造视为事后需要测量、评分或抑制的模型行为。

识别是一个不同的层次。它不对输出的可信度进行评分，而是通过要求每个声明声明它是什么以及它来自哪里，来改变模型首先被允许断言什么。这两个层次是互补的。一个识别做得好的流水线仍然受益于下游的校准和接地工作。一个只做下游工作的流水线是在过滤那些本不应以当前形式产生的输出。

## 对会议记录而言，识别是什么样的

观测数据中的识别是关于数据能够支持什么的问题。会议记录的识别是同一个问题，但范围收窄到了特定来源。给定这段会议记录，什么可以直接观察，什么可以在给定明确假设的情况下推断，什么根本无法被支持？

这就是全部的动作。摘要器产生的每个声明都应该声明它属于这三个类别中的哪一个。观察性声明指向会议记录中的特定段落，除了该段落所说的之外不做任何断言。推断性声明声明正在做出的假设以及推断所依托的证据。建议性声明声明它们是模型的建议，而不是参与者的决定。

一个无法将声明归入这些类别之一的摘要器，没有资格产生该声明。在这种情况下，正确的输出不是一个听起来更流畅的声明，而是没有声明。

这对摘要消费者来说是不舒适的，因为这意味着当底层对话内容单薄时，许多部分将会是空的。这种不适感正是重点所在。它是信息。它告诉读者，这次会议实际上没有产生八个部分的实质内容，无论摘要器多么想写出什么。

## 强制执行这种纪律的流水线

架构遵循这个框架。三个 LLM 阶段和一个确定性渲染器。

![图 1. 流水线架构：三个 LLM 阶段，一个确定性渲染器。图片来源：作者](https://contributor.insightmediagroup.io/wp-content/uploads/2026/05/fig1_architecture-1-1024x410.png)

第一阶段从会议记录中提取结构化事实：发言轮次、明确的承诺、明确的决策、明确的数量。这个阶段是刻意保守的。它可以遗漏一些东西，但不允许捏造。

第二阶段将这些事实综合成跨八个部分的声明对象。每个声明携带一个标签：观察性、推断性或建议性。每个声明携带一个指向提取事实中证据的指针。综合是分析工作发生的地方，也是模型最容易偏离的地方。

第三阶段进行审计。这是执行识别工作的阶段，而对它的约束是设计中最重要的部分。

*审计阶段不能将分析重写成听起来更流畅的形式。它不能添加更好听的建议。它不能捏造缺失的上下文。*

它被给予了一组有限的操作，除此之外被禁止做任何事情。它可以删除一个声明。它可以将声明从观察性降级为推断性，或从推断性降级为建议性。它可以将声明移动到更合适的部分。它可以用明确的"证据不足"占位符替换声明。它可以在整个部分没有任何内容通过审查时折叠整个部分。

![图 2. 审计阶段被允许应用的五种操作。不在此列表上的任何操作都被禁止，包括撰写更好的声明。图片来源：作者](https://contributor.insightmediagroup.io/wp-content/uploads/2026/05/fig2_operations-2-1024x563.png)

**`replace_with_insufficient_evidence` 操作值得单独说明。** 它是系统在输出中字面上键入一个占位符，取代曾经存在的自信声明。这就是识别工作被付诸实践。读者在文章中看到的正是综合阶段产生了一个来源无法支持的声明。

**为什么非对称性很重要。** 一个被允许改进分析的审查者会成为系统试图解决的同一问题的另一个来源。一个只被允许弱化或移除的审查者只能在一个方向上失败：过于谨慎。这是一种可以容忍的失败模式，反之则不然。

## 这种设计产生什么，以及它拒绝产生什么

这不是一个基准测试，而是一个小型基于 fixture 的压力测试，旨在检查架构是否产生了它被构建要产生的行为。三个会议记录不足以对 LLM 摘要做出一般性声明，但足以检查特定的设计选择是否有设计所预测的结果。

这些 fixture 是：一个在三个真实替代方案中选定了一种定价模型的决策会议；一个暴露了测量问题但没有解决的工作会议；以及一个几乎没有决策内容的简短两人同步会议。

**没有发生什么。** 在三次运行中，流水线产生了零个捏造的承诺和零个无依据的数量。这是架构被设计来使其更难发生的事情。如果声明没有指向证据的指针，它就无法通过流水线，而审计阶段无法制造证据来保持声明存活。结果不是保证——确定性渲染器是唯一能提供保证的阶段。提取、综合和审计仍然是 LLM 调用，仍然可能失败。重点是架构将其失败推向了移除而非捏造，fixture 与此一致。

**发生了什么。** 我发现更有趣的结果是弃权率。

![图 3. 弃权率随输入信号的稀薄程度而扩展。在三个 fixture 会议记录中，空部分槽的比例从 17% 上升到 58%。在所有三个 fixture 中：0 个捏造承诺，0 个无依据数量。图片来源：作者](https://contributor.insightmediagroup.io/wp-content/uploads/2026/05/fig3_abstention-1-1024x512.png)

在富有决策内容的会议中，流水线留下了 17% 的部分槽为空或替换为证据不足占位符。在工作会议中，这个数字上升到 25%。在简短同步会议中，它达到了 58%。当输入信号稀薄时，系统产生的空部分大约是输入信号丰富时的三倍半。

这正是设计试图产生的行为。无论输入如何都填满相同八个部分的摘要器不是在摘要，而是在生成符合模板的输出。模板在做工作，模型只是化妆品。

一个按照输入稀薄程度弃权的摘要器在做不同的事情。它将会议记录视为内容会变化的来源，并让这种变化体现在输出中。空部分不是模型的失败，而是模型拒绝断言来源不支持的内容。

![图 4. 在渲染输出中识别是什么样的。决策会议 fixture 的摘录，类别标签内联展示。图片来源：作者](https://contributor.insightmediagroup.io/wp-content/uploads/2026/05/fig4_example-1-1024x614.png)

**阅读结果。** 标签不是装饰，它们改变了读者对输出的处理方式。观察性声明邀请读者对照会议记录进行核实。推断性声明邀请读者审查产生它的假设。证据不足占位符邀请读者要么自己查看来源，要么接受这次会议实际上没有产生那种形状的声明。

## 来自消费者的异议

有一种论点认为空部分是可用性问题。读者期望得到摘要，却得到了一个带有明确空缺的部分摘要。读者不得不做更多工作。

这个异议值得直接回应。得到了八个部分的流畅摘要的读者已经在做更多工作了，只是以不可见的方式。他们会阅读摘要，采取行动，并在某个时刻发现两个行动项实际上没有被同意，一个风险从未被提出。这种发现的代价是高的——在错误分配的会议、遗漏的承诺以及对工具信任的缓慢侵蚀中付出代价。

诚实的空缺将代价前置。读者立即看到空缺，并可以决定如何处理。打开会议记录，询问参与者，将会议视为尚无定论——这些都比基于一个数据无法支持的置信度产生的摘要采取行动要好。

这与观测分析师在没有识别的情况下拒绝报告点估计时所做的权衡相同。消费者更希望得到一个数字，分析师拒绝了。消费者从没有数字做出的决定，平均而言，比他们从数据无法支持的数字做出的决定要好。

## 模式的推广

这个架构是可迁移的。任何从来源产生结构化声明的 LLM 工作流都可以被重新框架为观测分析，并赋予一个识别层。

用于法律发现的文件审查，患者病历摘要，客户通话分析，代码审查摘要——这些目前都被部署为一次性生成问题，模型从来源产生结构化输出，消费者信任结果。每一个都有与会议摘要器相同的失败模式的某个版本，每一个都可以通过类似的架构变得更可审计：一个对从来源提取的内容保守的提取阶段，一个生成带有证据指针的标记声明的综合阶段，以及一个被禁止添加或强化任何内容的审计阶段。不同领域的实现和风险概况有所不同，但模式是可迁移的，具体细节则不然。

标签和证据指针不是可选功能，它们是被付诸实践的识别步骤。没有标签的声明是不可识别的，没有证据指针的声明无法被审计。审计阶段的单调弱化约束防止了识别工作被一个想要产生更流畅输出的模型撤销。

## 这对构建这些系统的人意味着什么

校准不确定性估计是有价值的。幻觉基准测试是有价值的。接地和引用工作是有价值的。这些都无法替代拒绝产生来源不支持的声明的纪律。

这种纪律在许多 LLM 系统中缺失，部分原因是文化上的。这个领域从机器学习中发展起来，模型的目标是为每个输入产生一个输出。"正确的输出有时候是没有输出"这个概念对文献来说并不陌生，但对于一个被训练为填充接下来内容的生成模型的默认倾向来说是陌生的。然而，它对观测分析来说是本土的——在那里，许多问题的正确答案是数据无法支持答案。

因此，使 LLM 分析系统变得可信赖的技术可能主要不来自 LLM 文献内部，而可能来自那些已经弄清楚在来源是约束条件下进行诚实分析意味着什么的学科。因果推断是其中之一，调查方法论是另一个，法证会计是另一个。

*那些已经知道如何拒绝在没有识别的情况下进行估计的人，对于当前 LLM 分析工具的问题所在以及如何解决，拥有异常好的视角。*

因果推断教会了一代从业者不要估计他们尚未识别的内容。LLM 摘要器犯了同样的错误，只是用散文而不是数字。修复不仅仅是一个更好的模型，而是把观测分析从未放弃的那个步骤重新放回去，并用一个无法被说服做错误事情的架构来强制执行它。

## 几个结尾的陷阱

1. **将标签视为装饰。** 如果标签不在上游被强制执行，它们只是装饰。它们必须在综合阶段被赋予，同时附带证据指针，并在下游针对该指针进行审计。一个产生没有证据指针的标签的综合阶段不在做识别工作，而是在产生一个看起来像识别的类别。

2. **让审计阶段变得有帮助。** 这是容易犯的错误。一个能够添加建议、提供缺失上下文或重写笨拙声明的审查者感觉很有用，但这也恰好是综合阶段已有的失败模式，只是以质量控制的名义乔装打扮。将审计约束到一组固定的弱化操作上，其他任何操作都是系统在与自身争论。

3. **将弃权与低质量混淆。** 对于内容单薄的会议，大多数部分为空的摘要器没有失败。对于同样内容单薄的会议，产生自信的八部分输出的摘要器才是失败的，只是以不可见的方式。评估这些系统的方式不是摘要完整性，而是弃权率是否随来源中的信号强弱而变化。

4. **从三个 fixture 推断到一般性声明。** 三个会议记录足以检查设计选择是否产生了它被构建要产生的行为。它们不足以对 LLM 摘要做出一般性声明。如果你构建了这个系统的一个版本，你将需要你自己的 fixture 集和你自己对什么是正确的弃权水平的定义。

## 重要的非对称性

一个只能弱化其输出的流水线只有一种失败模式：过于谨慎。一个能够强化其输出的流水线拥有文献过去几年一直在记录的每一种失败模式。

选择第一种而不是第二种不是一个技术决定，而是一个关于系统用途的决定。如果系统是为了产生流畅的文字，第二种在每个指标上都会胜出。如果系统是为了产生读者在采取行动之前可以审计的声明，那么只有第一种是可辩护的。

大多数当前的工具是为了第一个目标而构建的，但部署时却表现得好像它是为第二个目标而构建的。将这种差距视为方法论问题而不是模型质量问题，才能改变可用的补救措施。
